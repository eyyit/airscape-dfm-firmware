# ESP-IDF 5.5.6 update review

Reviewed 2026-10-27. Source version is 0.4.2-dev. This is a build/test update,
not a device deployment or firmware release. No flashing, signing, provisioning,
publication, calibration or hardware security/eFuse changes are performed.

## Exact dependency change

ESP-IDF v5.5.5 (b774170ff46c393eeb5e495ea37936038d3f4f4f) is replaced by
v5.5.6 (880a203ae603d08a94d06aa01e0d6761958e5e9e). The official image is pinned
by digest in tools/build-env.json. Its Git HEAD was checked against the commit
resolved by the official v5.5.6 release tag, rather than trusting a mutable tag.

Release: https://github.com/espressif/esp-idf/releases/tag/v5.5.6
Comparison: https://github.com/espressif/esp-idf/compare/v5.5.5...v5.5.6

## Security and compatibility findings

Upstream identifies this as a v5.5 bugfix release. Its vulnerability fixes include
Wi-Fi supplicant hardening, Classic Bluetooth L2CAP length checks and TEE argument
snapshotting. Wi-Fi is relevant to this device. Classic Bluetooth is not used
(and ESP32-C6 is not a Classic Bluetooth target); TEE is not enabled here. This
is an applicability distinction, not a claim of exhaustive CVE coverage.

Targeted review included all 841 comparison commit subjects, the supplicant
security-fix patch and the changed Wi-Fi types used by the network worker.
Relevant changes include PMKSA/SAE handling, short FT/RRM frame validation,
RSSI-gain roaming behavior, disconnect/sleep fixes and flash cache/IRAM fixes.
HTTP-server changes clear freed URI-handler pointers on allocation failure and
reject zero-size query/cookie output buffers. I2C teardown now releases the
platform lock and retains resources safely when interrupt teardown fails.
Both components are used by this firmware; these implementation fixes matter
even though their public headers did not change.
Physical Wi-Fi, power-save, roaming and flash timing require hardware acceptance;
passing host tests cannot establish improved radio stability.

The reviewed I2C master, HTTP server and OTA public headers have no changes in
this comparison. The Wi-Fi station struct adds fields in previously reserved
bits; existing zero initialization leaves those features disabled. Published
breaking changes concern Key Manager on other chips and MAC_EXT byte order on
ESP32-C5, not features used by this ESP32-C6 application.

The SDK adds WIFI_AUTH_UNKNOWN for invalid/unparseable scan authentication.
Our previous numeric minimum check would have accepted it as a roaming candidate.
The application now rejects UNKNOWN and higher/sentinel values. Host doubles
match the new enum values, and fault tests cover UNKNOWN and MAX without a
reconnect. Existing valid WPA2 roaming and OTA scan guards remain tested.

Supplicant patch:
https://github.com/espressif/esp-idf/commit/1e7ba7041331902878ea49cb1fdec6b36bf76014

## Licensing and validation

All 46 preserved SDK legal files were re-read from the exact 5.5.6 image and
hash-compared. Their paths and bytes are unchanged; inventory.json now records
the new SDK version, image digest and commit. The project's Apache-2.0 LICENSE
and the upstream licenses are unchanged. THIRD_PARTY.md tracks the new provenance.

Required validation uses a clean tracked-source clone: license integrity,
privacy/history secret scans, Python style, host fault/integration tests and
coverage, two clean application/bootloader/partition builds with exact binary
comparison, and checks that generated outputs contain no private settings.
CI remains source-only for publication and uploads validation reports only.
The private deployment header, Wi-Fi credentials and signing keys are unchanged.
Hardware acceptance and a separately authorized signed deployment remain pending.
