# Contributing

Contributions are welcome through reviewed pull requests. By intentionally
submitting a contribution for inclusion, you offer it under Apache-2.0 unless
explicitly stated otherwise, consistent with section 5 of LICENSE. Preserve
upstream copyright/license notices. Do not submit code you cannot license.

Use synthetic identities and reserved example addresses. Never submit device
credentials, signing keys, private provisioning, captures or installation logs.
Report security issues privately as described in SECURITY.md.

Python uses two-space indentation, single quotes and 80-column lines. Run Ruff,
host tests, coverage, privacy/license checks and clean reproducible builds before
requesting review. Host tests are not hardware acceptance or RF/flash evidence.
Sampling and metrics must outrank diagnostics. Do not add undocumented pressure
relationships, automatic calibration or dirty-filter inference.

Keep SDK upgrades separate and refresh exact-version third-party notices.
CI cannot deploy. Firmware distribution requires an independent release review.
